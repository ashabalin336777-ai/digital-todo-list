# Список задач

Версия 1.0. Тестовое задание для компании Digital.

Веб-приложение ведёт личный список дел в браузере: задачу можно добавить, отметить выполненной и удалить. Список хранится на этом устройстве и возвращается после перезагрузки страницы.

Стек — чистые HTML, CSS и JavaScript, без фреймворков и сборщиков. В контейнере страницу отдаёт nginx.

Интерфейс на русском. Карточка стоит по центру и остаётся удобной от ширины 360px до десктопа. У кнопок и полей есть состояние фокуса с клавиатуры.

## Функции

- Добавление задачи кнопкой «Добавить» и клавишей Enter. Пустая строка и строка из одних пробелов не добавляются. Пробелы по краям обрезаются.
- Отметка «выполнено» чекбоксом у каждой задачи. Выполненная зачёркивается и становится бледнее. Повторный клик снимает отметку.
- Удаление кнопкой «Удалить» у каждой задачи.
- Сохранение в `localStorage` под ключом `todo-tasks`. После обновления страницы список на месте.
- Битые данные не ломают страницу. Если JSON повреждён, это не массив или запись без нужных полей, приложение начинает с пустого списка либо пропускает только испорченную запись.
- Счётчик «осталось N из M»: N — незавершённые задачи, M — всего.
- Надпись «Задач пока нет», когда список пуст.
- Текст задачи выводится через `textContent`, без `innerHTML`, поэтому разметка в тексте не выполняется.

## Формат задачи

Каждая задача — объект с четырьмя полями:

```json
{
  "id": "cbfd6f32-ffd0-4fd8-90bf-249b1aebcb16",
  "text": "Купить молоко",
  "done": false,
  "createdAt": "2026-11-18T08:33:14.194Z"
}
```

`id` — `crypto.randomUUID()`, если браузер его поддерживает. `createdAt` — время создания в ISO-формате. В `localStorage` лежит массив таких объектов.

## Запуск локально

Откройте `index.html` двойным щелчком. Страница не ходит на сервер: данные остаются в `localStorage` браузера.

Либо поднимите статический сервер из корня репозитория:

```bash
python -m http.server 8080
```

Сайт откроется на http://localhost:8080.

## Запуск через Docker

Нужен запущенный Docker. В корне репозитория:

```bash
docker build -t todo .
docker run -p 8080:80 todo
```

Образ основан на `nginx:alpine`. Файлы `index.html`, `style.css` и `app.js` копируются в `/usr/share/nginx/html`. Контейнер слушает порт 80, снаружи это http://localhost:8080.

Остановить контейнер, запущенный в этом терминале: `Ctrl+C`.

## Деплой на Timeweb Apps

Приложение рассчитано на [Timeweb Cloud App Platform](https://timeweb.cloud/docs/apps/deploying-with-dockerfile). Сервис собирает образ из `Dockerfile` в корне репозитория и направляет внешний трафик портов 80 и 443 на порт из `EXPOSE`. В этом проекте nginx слушает порт 80.

1. Зайдите в [панель Timeweb Cloud](https://timeweb.cloud/) и откройте раздел App Platform.
2. Нажмите «Создать» и подключите GitHub-аккаунт, если он ещё не подключён.
3. Выберите репозиторий `digital-todo-list` и ветку `main`.
4. Оставьте сборку по Dockerfile. Файл лежит в корне, в нём указано `EXPOSE 80`.
5. Нажмите «Запустить деплой» и дождитесь готовности во вкладке «Деплой».
6. Адрес и технический домен появятся на вкладке «Дашборд».

Документация: [деплой из Dockerfile](https://timeweb.cloud/docs/apps/deploying-with-dockerfile).

## Использованные AI-инструменты

Первая версия подготовлена в редакторе Cursor с помощью AI-ассистента.

Ассистент написал разметку, стили, логику списка, Dockerfile, `.dockerignore` и этот README. Отдельно проверены сценарии в браузере: добавление кнопкой и по Enter, отказ от пустых строк, отметка и снятие «выполнено», удаление, сохранение после перезагрузки, битые данные в `localStorage` и вывод текста без HTML. Образ Docker собран и отдаёт сайт на порту 8080.
